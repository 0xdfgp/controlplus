## How to read this

- The audio row was measured on synthetic speech. The voice fixture is generated by OpenAI text-to-speech from a committed script, not recorded from a person. It is a valid measure of the latency, cost and integration effort of the transcription hop, and it says nothing about recognition accuracy on an older voice, which ADR-018 records as exactly where on-device quality diverges.
- First token means the first chunk of visible answer text, not the first event on the stream. It is what the person waits for, and the same thing ADR-021 measured when it found 18 to 52 seconds of dead air.
- Reasoning tokens are what each provider reports, not an independent measurement. Anthropic bills reasoning inside output_tokens and reports no separate count, so its reasoning column is zero rather than small. Gemini reports thinking separately. OpenAI reports it inside output_tokens, and the harness subtracts it so the three columns sum to the provider total rather than double counting.
- Costs are estimates against published prices, read from each provider on the date above. They are a snapshot, not an integration with billing, and they are priced in three parts because providers bill them in three parts.
- Layer one is deterministic and runs in code. A layer one failure fails the case and the judge is not invoked, per ADR-033, so an empty layer two cell on a failed row means the judge was never asked rather than that it had no opinion.
- No headline verdict was self-judged. With three families and four candidates, no single judge covers all four without grading its own family, so three candidates share the OpenAI judge and the OpenAI candidate is judged by Gemini. That asymmetry is real: the OpenAI row is not graded by the same instrument as the other three.
- Every answer was also graded by the other judge, and that second verdict is reported beside the first but never counted. It is there because a pilot run showed the two judges disagreeing systematically rather than occasionally, which would have made a single-judge table attribute a judge effect to the candidate. Where the second judge shares the candidate's family, the cell says self-judged and the verdict is excluded from every total.
- A judge measures conformity to a rubric written by the architect, not whether a 78 year old was actually helped. Only user testing settles that.
- Candidates ran sequentially. Concurrent requests contend for the same connection and rate limit, and a latency measured under self-inflicted load is not the number anyone wants.
- The two Anthropic candidates ran through the shipped adapter and its opener, including max_tokens of 2048 and no thinking parameter. That is the product path as wired today (ADR-032). Claude Opus 5 thinks by default when no thinking parameter is sent, and max_tokens caps thinking and answer text together, so a truncated Opus row is a finding about the shipped configuration rather than about the model.
- Calibration is not included. ADR-033 asks for ten hand-labelled responses and an agreement rate against the judge; the labels are the architect's to make. Every answer and every verdict is in the JSON results file so that pass can be done against this run.
